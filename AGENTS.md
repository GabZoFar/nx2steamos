# Notes for agents

- This repository ports a player's own Switch games to **SteamOS**, natively, with two engines. **ARM64 SteamOS**: nxnative's engine (the rewriter `nxnative/dm/tools/patch_nso.py`, the Horizon host `nxnative/dm/host`, the NVN layer `nxnative/dm/gfx`) with nx2android's Vulkan backend (`nxnative/dm/android/gfx_vk_*.c`) and nx2steamos's SteamOS runtime (`nxnative/dm/steamos`), built per game by the port pipeline (`porter/`). **The Steam Deck** (x86-64): Savage Wind Recomp's static recompiler and runtime in `recomp/` ([docs/RECOMP.md](docs/RECOMP.md)), which the porter does not drive yet. [README.md](README.md) is the player's page, [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) the design and its layer rules, [RESEARCH.md](RESEARCH.md) the platform facts with sources, [docs/ENGINE.md](docs/ENGINE.md) and [docs/RECOMP.md](docs/RECOMP.md) what is vendored and changed, [docs/ROADMAP.md](docs/ROADMAP.md) what comes next.
- Where to start:

  | A game that does not reach its frame loop | `nxnative/docs/agents/03-bringup.md`, run headless over SSH (`DM_HEADLESS=1 ./nx2steamos-run`) |
  | The SteamOS runtime (window, input, audio, pools, Steam) | `nxnative/dm/steamos/README.md`, then [ARCHITECTURE.md](docs/ARCHITECTURE.md) "The runtime" |

  | Another game | `python -m porter port <folder> --experimental`, then "Adding a game" in ARCHITECTURE.md |
  | The Steam Deck engine (recompiler, runtime, a game on it) | [docs/RECOMP.md](docs/RECOMP.md), then Savage Wind's own notes `recomp/docs/SAVAGE-WIND.md` (Spanish) and `recomp/docs/linux.md`; its log is `~/.local/share/nx2steamos/<title ID>/savagewind.log` for a port (`~/.local/share/savagewind/` for Savage Wind's own app) |

- **The engine is shared.** `nxnative/` is nx2android's copy of nxnative; keep changes to its shared files small, behind `__linux__` / `__ANDROID__` / `DM_STEAMOS`, and list each one in [docs/ENGINE.md](docs/ENGINE.md): they should be acceptable to nx2android as general Linux support. New SteamOS code goes in `nxnative/dm/steamos/`. Upstream's own rules hold inside the engine (`nxnative/AGENTS.md`): per-game values in the profile, per-build knowledge keyed by the NSO build ID, general fixes over game-specific rules, root causes over workarounds.
- **The Steam Deck engine is vendored too.** `recomp/` is Savage Wind Recomp's tree at the commit [docs/RECOMP.md](docs/RECOMP.md) names; change it as little as possible and list each change there, so later upstream commits still apply. Its generated C (`generated*/`) is made from a game's code and never enters the repository, like the game's files (`recomp/.gitignore`). Its checks run in the amd64 dev container: `sh devtools/check.sh deck`. A change to its generator or the headers the game code is compiled against changes the game code id (`porter/deck.py` `gamelib_id()`): Savage Wind's release runtime then no longer loads the porter's game code (`tests/test_deck.py` fails), and the Deck's game folders need a runtime built from `recomp/`.
- **Profiles are data.** A game's SteamOS keys go in `nxnative/dm/games/<title ID>/steamos.tsv` (`nxnative/dm/steamos/tools/steamos_profile.py`); no title IDs or game names in the runtime's code (`tests/test_architecture.py`).
- **Game files and keys never enter the repository**, nor anything extracted from them (RomFS, modules, shaders, dumps). They stay in the game's folder and its `<title ID>_build/`. Do not print key values. 
- **Checks.** `sh devtools/check.sh` (arm64 Docker) runs everything that needs no device: both host builds, the host's unit tests on glibc (`nxnative/dm/steamos/tools/host_tests.py`), the rewriter's tests, the porter's tests (`python -m unittest discover tests`) and the probes on lavapipe. A change to the runtime or the engine runs it; say what it reported. Device facts come from `probes/` on a device, never from the container (its GPU is lavapipe, its counter 24 MHz, its kernel Apple's VM).
- **The overlay's shaders** are committed SPIR-V (`nxnative/dm/steamos/gen/`): after changing `nxnative/dm/android/shaders/*`, run `python3 nxnative/dm/steamos/tools/gen_shaders.py` in the dev container (build.py refuses stale headers).
- **Steam.** `porter/steam.py` runs on the device with the system's Python: standard library only. Write `shortcuts.vdf` only with Steam stopped; with Steam running, ask Steam to add the game (`steam://addnonsteamgame/`). Keep the player's original file (`shortcuts.vdf.nx2steamos-backup`).
- **Reverse engineering with REA.** For bring-up (a crash in game code, a function to cut or stub, the same function in another build), [REA](https://github.com/morluto/rea) gives Ghidra / Hopper / IDA over MCP (`npx rea-agents setup`; the user's checkout is `../rea`):
  1. Convert a module to ELF, in the game's work folder: `python3 nxnative/dm/tools/nso2elf.py <id>_build/extract/<ver>/ExeFS/main <id>-work/main.elf`.
  2. Open it with REA (`open_binary`), then `list_procedures`, `analyze_function` at the address the host's crash log gives (`main+0x…` is relative to the module's base), `xrefs` / `procedure_references` for who calls it, `read_bytes`.
  3. Carry a rewriter cut to a new build: `list_procedures` on both builds' ELFs, then `match_native_functions` (the engine's own `nxnative/dm/tools/nso_fnmap.py` does the same from the command line); check the result by disassembly before registering the cut for the new build ID.
  REA's evidence stays local; never attach game code or its decompilation to an issue.
- **Devices.** The user tests on their own SteamOS device; installing over SSH is the user's choice (`porter config device`). Do not write to a device's Steam configuration, restart Steam or install games without being asked.
- Everything is in English: docs, comments, log lines. Log lines for something wrong or unimplemented start with `[RED] `.
- Commit only when asked. Commit messages follow Conventional Commits (`feat(steamos): …`, `fix(vk): …`), as nx2android's.
